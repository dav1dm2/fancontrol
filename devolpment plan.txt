# 1. First: what are you actually building?

i have been tasked to build an api, however, i would like to build an application as well
in order to demonstrate the API in action. 
this application must be very simplified in order to only demonstrate its core functionalities

my idealized appliction: a fan controller app.

this app would provide central control managing tool for managing micro controller devices
for activating and de-activating multiple fans

imagine a esp32 with a relay and a sensor(a simulated one could be a button any sort of input should do) to represent a single device, now think of a way to control 2 or more of these devices

these devices would connect to a single "master" where the app would be hosted, the devices would provide the state of the sensor, and the state of the fan, but not take any decision to flip the state of the fan, that would come from the "master"

the app must:
connect new devices,
receive data from these devices,
provide the command to flip the relay,
record the time of the last recieved input

human actors must be able to access this app and see a basic managing platform for their system.
-see current state of the relay
-see last sensor activation
huaman actors must be able to manually flip the relay state.


/*
Definition:
A centralized fan management system that allows a human operator to monitor and control multiple network-connected microcontroller devices. Each device controls a physical fan and reports its sensor and fan state to a central Spring Boot application. The central application is responsible for deciding the desired fan state and sending commands to the devices.

*/

6-What rules does your application have?
 i might need more but i thought these were good

> A device must have a name.

> A device's status can only be `ONLINE` or `OFFLINE`.

> Two devices cannot have the same name.

> The device itself does not decide whether the fan should turn on or off.

> Only the central application can issue a fan-control command.
